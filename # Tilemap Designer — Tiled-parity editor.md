# Tilemap Designer — Tiled-parity editor for Bixel Studio ## Goal A dedicated **Tilemap Designer** for `.map` documents: Tiled-style multi-layer tile editing with tileset stamping, region copy/paste, and game-engine-agnostic export (Tiled JSON + CSV + PNG). Built by reusing the existing Rust tilemap math, the CALayer canvas, the viewport, and the Procreate-style chrome — same design language, same architecture contract (Swift sends commands; Rust processes whole buffers). ## Architecture ``` TileMapCanvasView (CALayer) → TileMapModel (Swift) → TileMap engine (FFI) ↓ bixel-core/src/map.rs (TileMap) reuses tilemap.rs primitives ``` On-disk format: **the project document IS a Tiled 1.10 orthogonal JSON map** (uncompressed GID arrays, like `map_validate::new_document`). Saving and exporting are the same bytes — any engine with a Tiled importer (Unity, Godot, Phaser, SpriteKit via JSTileMap, etc.) reads it directly. Tileset images are project asset files referenced by relative path (the workflow `map_validate::tileset_image` already expects). ## Phase 1 — Core designer (stamp, copy, export) ### 1. Rust: `crates/bixel-core/src/map.rs` (new, ~700 lines) ```rust pub const GID_H_FLIP: u32 = 0x8000_0000; // Tiled flip flags pub const GID_V_FLIP: u32 = 0x4000_0000; pub const GID_D_FLIP: u32 = 0x2000_0000; pub struct Tileset { first_gid, name, image, image_width, image_height, tile_width, tile_height, margin, spacing, columns, tile_count, #[serde(skip)] pixels: Vec<u8> } // RGBA, uploaded via FFI pub enum MapLayer { // tagged serde enum — object layers slot Tile(TileLayerData), // in later without a schema break Objects(ObjectLayer), // (phase 2; parse + round-trip in ph.1) } pub struct TileLayerData { id, name, visible, opacity, layer: tilemap::TileLayer } pub struct ObjectLayer { id, name, visible, opacity, objects: Vec<MapObject> } pub struct MapObject { id, name, kind (Rect|Point), x, y, w, h, properties } pub struct TileMap { width, height, tile_width, tile_height, layers: Vec<MapLayer>, tilesets: Vec<Tileset>, next_layer_id, next_object_id, undo_stack, redo_stack, max_undo } ``` API: - `new(w, h, tw, th)`; `snapshot()/undo()/redo()/can_undo/can_redo` (clone pattern from `document.rs:440`). - `add_tileset(...) -> Result<usize>`: computes `columns`/`tile_count` from image size + margin/spacing (`slice_tileset_math`, pure fn, unit-tested); assigns `first_gid` after the previous tileset; `set_tileset_pixels(idx, rgba)` stores the upload for compositing. - `gid_lookup(gid) -> Option<(tileset_idx, local_id, flags)>`; `encode_gid(local, flags)`. - Edit ops (delegate to `tilemap.rs`): `set_tile`, `stamp(layer, x, y, &Pattern, skip_empty)`, `fill`, `paint_rect`, `paint_line` (drives `line_cells` + `set_tile`), `replace`, `read_region -> Pattern`. - Layer ops: add/remove/rename/reorder/set_visible/set_opacity. - Persistence: `to_tiled_json() -> String`, `from_tiled_json(&str) -> Result<TileMap>` — serde structs, `"type":"map"`, `"version":"1.10"`, `"orientation":"orthogonal"`, `"infinite":false`; unknown fields preserved via `#[serde(flatten)] extra` so files from real Tiled round-trip losslessly. Object layers parse in phase 1 (so Tiled files load) even though object *editing* is phase 2. - `composite(into: &mut [u8])`: back-to-front blit of visible tile layers from tileset pixel buffers, honoring opacity + flip flags, nearest sampling. Output = `width*tile_width × height*tile_height` (bounded by the existing 4096² document cap). - `layer_to_csv(layer) -> String`. Tests: `crates/bixel-core/tests/map_test.rs` — JSON round-trip (incl. through `map_validate::tile_layers`/`tileset_meta` as schema check), GID flag encode/decode, margin/spacing slicing math, multi-layer stamp/copy/paste via `Pattern`, undo/redo, composite pixel-correctness on a synthetic 2×2 tileset, CSV output, loading a Tiled-produced file with extra fields. ### 2. switch to changed-index deltas (edit fns already return them) only if profiling says so. - `bixel_map_composite` cost at 4096² ≈ 67 MB buffer — compositing is keyed off `canvasRevision` like the sprite canvas, so it only runs on change; acceptable on the CALayer path. - Tiled JSON arrays are uncompressed in v1 (valid, human-diffable, matches `map_validate` expectations); zlib/base64 arrives with TMX in phase 3. - `AGENTS.md` says Metal/MTKView but the canvas is actually CALayer — the plan follows the real code and keeps the buffer contract.
